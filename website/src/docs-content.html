Portable semantics, replaceable runtimes.

The core accepts evaluate requests for typed decisions and generate requests for scalar workflows. It validates dependencies, conditions, nullable values and workload limits. An adapter renders the model's real prompt and tokenizer, returns candidate scores, and lets TurboJev validate, normalize, calibrate, and build the response.

Core owns

  • Schema, candidate and dependency validation
  • Execution planning and calibration metadata
  • Typed responses, conditional omissions and scalar validation
  • Order robustness and parity contracts

Adapters own

  • Chat template and tokenizer
  • GGUF, Transformers.js, or custom runtime
  • Media preprocessing and hardware
  • Process, file, and network boundaries

Choice, boolean decision and ordered score

Canonical request 
{
  "state": "Everything is down and our biggest client has a demo at noon.",
  "questions": {
    "urgent": { "type": "noul", "instructions": "Does this need a reply within the hour?" },
    "team": {
      "type": "choice",
      "instructions": "Which team should handle this?",
      "criteria": {
        "outage": "Service down",
        "billing": "Charges and refunds",
        "feature": "Requests and how-to"
      }
    },
    "tone": {
      "type": "score",
      "instructions": "How upset is the customer?",
      "criteria": ["calm", "annoyed", "furious"]
    }
  }
}

choice selects a semantic key and returns its relative probability distribution. Exact ties select the lexicographically smallest key. noul returns a boolean-decision probability; boolean is an input alias. score returns the expected zero-based index: sum(index × probability). Its criterion order defines the scale; changing that order changes the meaning.

Finite decisions versus generated fields

Use generate for strings, integers, numbers, nullable values, finite enums, dependencies and conditional fields. Finite fields score candidates; open strings and numbers generate bounded tokens. A numeric enum is an unordered choice, not an ordered score.

Candidate probabilities are conditional on the supplied options, not calibrated confidence. Option ordering explains the default single pass and optional corrections. Decision design explains prompt construction, legal actions and testing.

Use the idioms of your host.

Each binding owns lifecycle and host ergonomics. The request and response semantics stay the same.

Make a decision

main.rs 
use turbojev::TurboJev;
use turbojev_runtime_llamacpp::{ffi::{FfiLlamaCpp, NativeConfig}, reference_backend, ReferencePromptConfig, ReferencePromptRenderer};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let runtime = FfiLlamaCpp::open("./model.gguf", NativeConfig::default())?;
    let renderer = ReferencePromptRenderer::new(ReferencePromptConfig::new(
        "my-app-v1", "Choose exactly one allowed code.", "Which team should handle this?"));
    let engine = TurboJev::new(reference_backend(renderer, runtime));
    let request = turbojev::schema::EvaluationRequest {
        model: None,
        state: serde_json::json!({"message": "My package arrived broken."}),
        questions: [("department".to_owned(), turbojev::schema::Question::choice(
            "Which department should handle this?",
            [("billing".to_owned(), "Payments".to_owned()), ("shipping".to_owned(), "Delivery".to_owned()), ("other".to_owned(), "Other".to_owned())].into_iter().collect(),
        ))].into_iter().collect(),
    };
    let answer = engine.evaluate(request)?;
    println!("{:?}", answer.answers);
    Ok(())
}

C ABI

Stable UTF-8 JSON ABI for C, Zig, Go, and other FFI hosts.

header ↗
smoke.c 
#include "turbojev.h"
#include <stdio.h>

int main(void) {
    tj_engine *engine = NULL;
    if (tj_engine_open_json("{\"model\":\"./model.gguf\"}", &engine) != TJ_OK) return 1;
    char *json = NULL;
    const char *request = "{\"state\":{\"message\":\"My package arrived broken.\"},\"questions\":{\"route\":{\"type\":\"choice\",\"instructions\":\"Which team?\",\"criteria\":{\"billing\":\"Payments\",\"shipping\":\"Delivery\"}}}}";
    int rc = tj_engine_evaluate_json(engine, request, &json);
    if (rc == TJ_OK) { puts(json); tj_string_free(json); }
    tj_engine_close(engine);
    return rc != TJ_OK;
}

The ABI uses opaque handles, explicit string ownership, and thread-local errors.

Try the browser playground

The playground runs real inference in a worker. Select the input type before loading a model. Unload the current model to change it. Downloads start only when you press Load.

Model selection

Input Models Method
Text · ONNX Qwen2.5 0.5B, Qwen3 0.6B Transformers.js candidate-token logits
Text · GGUF Qwen3 0.6B Q8_0 llama.cpp WASM constrained-answer log-probabilities
Image CLIP B/32, CLIP B/16 Image–text similarity
Image · GGUF LFM2-VL 450M Q4_0 + mmproj llama.cpp WASM mtmd image input
Audio CLAP HTSAT Sound–text similarity
Audio · GGUF LFM2 Audio 1.5B Q8_0 + mmproj Wllama mtmd audio input; real Node/WASM probe passed, browser qualification pending
Video CLIP or LFM2-VL GGUF Four ordered, timestamped frames; no audio track

Media limits

Files must be at most 24 MB. Audio is mixed to mono at 48 kHz and must be 10 seconds or shorter. Video must be 60 seconds or shorter; the llama.cpp path sends four ordered, timestamped frames to mtmd. This does not guarantee temporal understanding and ignores the audio track. Small models can return incorrect decisions.

Runtime assets

The package supplies the worker bridge. The example uses matching published 0.31.0 WASM and GGUF adapter assets from jsDelivr. Use a bundler that emits the package worker on your own origin; if serving plain HTML, host the package worker locally and set workerUrl. You can host the WASM and adapter assets yourself instead. The repository includes Transformers.js and llama.cpp WASM adapters. The llama.cpp adapter loads a matching mmproj for supported image models and passes video as ordered, timestamped image frames. A native Windows x64 LFM2 Audio Q8_0 probe passed four real audio decisions with cyclic candidate-order handling. For browser media, either supply evidence bytes in the envelope or use the direct runtime media hook as the playground does. GGUF audio is forwarded when Wllama detects an audio encoder, with media before prompt text. Wllama 3.8.1 reserves workers for audio preprocessing. A real LFM2 Audio probe passed four decisions through the adapter and Rust core in Node/WASM; the corrected browser page still requires a fresh run. The playground offers none, cyclic and balanced ordering for choice questions, including media. Corrections add real model evaluations; none is the default. The local site uses py website/serve.py to set WebAssembly threading headers. Select the llama.cpp runtime and a GGUF model in the playground; the browser loads the model locally from Hugging Face. The samples/build.py web command prepares the TurboJev WASM assets.

Troubleshooting

If WebGPU is unavailable, select CPU. If initialization runs out of memory, unload the model and try a smaller GGUF quantization. Cancel terminates the worker. Model downloads may take several minutes and require enough browser memory.

Evidence formats

Input Envelope Runtime requirement
Image modality: "image", base64 Vision encoder and matching projector
Audio modality: "audio", base64 Supported audio model/projector and audio decoding
Video frames modality: "video", frames: [{timestamp_ms, base64}] Vision runtime; host decodes frames in timestamp order

Optional text provides context alongside media. Video containers must be decoded by the host; TurboJev does not invoke ffmpeg/ffprobe executables. Ordered frames do not prove motion understanding and do not include the audio track.

Typed extraction

For generate, place the same envelope in context and define scalar fields, such as a receipt total and currency. The response uses result, not answers. Field workflows preserve media bytes while adding dependency answers. Set thinking: false; native media reasoning and browser reasoning return an explicit unsupported error.

The playground offers CLIP/CLAP similarity and LFM2 vision/audio GGUF paths. Similarity models do not follow arbitrary instructions. Browser audio GGUF remains experimental: the recorded Node/WASM adapter probe is not equivalent to qualification in every browser. Downloads, memory and preprocessing can dominate latency. Typed fields and workflows

Structured SDK extensions describe source version 0.32.0, awaiting publication. Build this revision to use the new APIs; registry demos retain published packages.

generate adds JSON-typed fields to TurboJev's portable core. evaluate remains the direct choice, noul and ordered score API. Finite fields score model candidates; unrestricted strings and numbers generate a bounded value. Extraction therefore generates tokens and can take longer than a single candidate decision.

Request and response

from turbojev import TurboJev

with TurboJev.load("invoice.gguf", device="cpu", n_ctx=8192, n_seq_max=1) as client:
    response = client.generate(
        context="Invoice total: 324.50 GBP. Payment is overdue.",
        questions={
            "total": {"type": "number", "instructions": "What is the total in GBP?"},
            "overdue": {"type": "boolean", "instructions": "Is payment overdue?"},
            "reminder": {
                "type": "string",
                "when": {"overdue": True},
                "depends_on": ["total"],
                "instructions": "Write one short payment reminder.",
            },
        },
        thinking=False,
        text_max_tokens=128,
        numeric_max_tokens=64,
    )
    print(response["result"])
    print(response["skipped"], response["usage"])

The same JSON request is accepted by every binding. Supply exactly one of questions (a field map) or schema (an object with properties, optional required, and optional additionalProperties: false). All declared properties are requested; required validates property names, not a separate omission policy. Conditions control omissions. The schema subset supports scalars, nested objects and top-level arrays; nested arrays and arrays inside objects are rejected. Exact finite-value ties compare JSON value encodings; probabilities are not rounded into artificial ties. state is an input alias for context.

Field option Behavior

enum 1–512 unique values of that type; a singleton is a constant with no model scoring
instructions / description Question; description is the fallback
depends_on Names of earlier results to include as plain values; forward references allowed

Token limits are request-level text_max_tokens (default 256) and numeric_max_tokens (default 64), each 1–32768. Booleans default to [true, false], plus actual null for nullable booleans. Numeric equality distinguishes booleans from integers and does not round distinct 64-bit integer values. Unsupported keywords, including bounds, string length/format constraints and unsupported container combinations, are rejected before inference rather than ignored. Invalid generated output and exhausted budgets are errors.

Wllama 3.8.1 exposes top-N vocabulary scores and its Jinja autoparser does not apply custom GBNF on this path. The adapter resolves letter labels through the loaded model tokenizer using textual logit-bias keys, applies the same additive offset to every permitted label, and requests post-sampling probabilities with truncation disabled. A common offset preserves candidate log-odds and the conditional distribution; it does not favor the first option or select a winner. This uses one model call for 2–26 candidates. Missing or invalid scores are errors, never invented probabilities. The browser adapter does not claim a selective output head.

Objects, arrays and scales

Object leaves use scoped dependency names and return the original nested shape. Top-level arrays accept scalars or grammar-constrained objects. They support minItems, maxItems and continue_from; without a maximum, each call can append at most 50 new items. Duplicates stop deterministic extraction; sampling permits two retries. The model supplies every item.

structured.json 
{
  "context": "Ada is 37 years old and says she is furious.",
  "questions": {
    "person": {
      "type": "object",
      "properties": {
        "name": { "type": "string" },
        "age": { "type": "integer" }
      }
    },
    "tone": {
      "type": "number",
      "levels": [
        { "label": "calm" },
        { "label": "annoyed" },
        { "label": "furious" }

      "return_probabilities": true
    }
  }
}

Described choices use choices: [{value, description}] instead of enum. A number field with 2–26 ordered levels returns the expected zero-based level. It cannot be permuted. Large text enums (27–512) need complete continuation scoring: native GGUF and ONNX implement it; GGUF/WASM requires an explicit value-scorer plugin. They have a higher cost than one-token decisions.

Dependencies, conditions and null

Dependencies form a validated acyclic graph. A dependent prompt receives only its named previous answers, without probability wrappers. The media envelope and its bytes stay intact. Fields currently execute serially in dependency order; this API does not promise shared-prefix batching or parallel field generation. Response fields return in caller order.

json 
{
  "context": "The account has seven overdue invoices.",
  "questions": {
    "count": { "type": "integer", "instructions": "How many invoices?" },
    "escalate": {
      "type": "boolean",
      "when": { "count": { "gte": 5 } },
      "instructions": "Should support escalate this account?"
    },
    "reference": {
      "type": ["string", "null"],
      "instructions": "Return the payment reference, or null when it is absent."
    }
  }
}

Tests support equality, list membership, and objects with in, not_in, ne, gt, gte, lt, lte. Comparison operands are type-checked. Open string fields may be tested for null, but not arbitrary string equality. A false condition skips the field and all its dependents without inference, including automatic effort selection. Skipped fields are absent from result and named in skipped; they are not invented null answers. Actual null is present in result. The string "null" stays a string.

Probabilities and permutation budgets

json 
{
  "type": "string",
  "enum": ["heads", "tails"],
  "instructions": "Which side of a fair coin will appear?",
  "permutations": "all",
  "return_probabilities": true
}

The result wrapper contains value, confidence, probabilities and distribution. distribution is an array of {value, probability} retaining actual JSON types. Map keys normally use string values or JSON spellings for other scalars. In nullable string enums, the literal string "null" uses the quoted map key "\"null\"" to distinguish it from actual null's "null" key. Prefer the typed array if keys matter.

Each ordering receives a real model evaluation. Scores are normalized separately, remapped to original values, then probabilities are averaged. auto uses canonical ordering and a Williams design: N evaluations for an even N, 2N for an odd N greater than one. Integer budgets sample distinct orderings reproducibly using request seed; the identity is included. all visits every permutation. A hard cap of 720 prevents accidental factorial workloads. A six-sided die with all costs 720 evaluations; opt in deliberately. Averaging may reduce position bias but does not guarantee correct reasoning or calibrated confidence. This policy is separate from evaluate's load-time none, cyclic and balanced policies. Positive integer budgets include the caller listing and are not generally order invariant; use auto for canonical layouts. Numeric enums are unordered, unlike score. See option ordering.

Confidence, sampling and SDK helpers

Probability output defaults to permutations: "auto" for small unordered fields unless a budget is explicit. Set permutations: 1 for one pass. Large enums and ordinal scales default to one pass.

The wrapper separates raw selected probability from confidence. Choice confidence measures the top probability above uniform; ordinal confidence measures dispersion around the modal level. Neither is fitted calibration. A when confidence gate uses numeric bounds in 0–1 and requires probability output on its parent.

Request temperature defaults to 0. Positive temperature samples finite decisions using seed. Native GGUF supports seeded open values; the ONNX adapter explicitly rejects that open-value mode.

Python adds Choice, compiled Decision/ArrayField, Generation/Usage, compile_json_schema, candidate_softmax, run_schema, example_schema, encode_image and benchmark_prefix_cache. Node exports model-free compileJsonSchema and candidateSoftmax. C# adds CompileSchema, CandidateSoftmax and typed GenerateAsync. C/WASM expose JSON compiler/normalizer functions. Existing JSON methods remain available.

Python generation accepts a timeout or a thread-safe GenerationControl. Node/browser accept {timeoutMs, signal}; C# accepts TimeSpan and CancellationToken. Cancellation is cooperative before/after model operations; an active decode must finish. Browser workers serialize requests and process cancellation messages separately.

The optional images request accepts up to 32 encoded images in order. Python encodes bytes, paths, data URIs or PIL-like objects; browser imageEvidence encodes Blobs. Load a compatible vision model plus projector. URLs are fetched explicitly by the application.

Thinking and runtime capabilities

Default generate thinking is false, independently of the load-time policy used by evaluate. A field can override the request. Budget-only field overrides inherit the request's on/off setting. Effort selects the setting explicitly. Contradictory settings fail validation. auto asks the model to choose none/low/medium/high as an additional hidden finite decision, exposes that selection in thinking_effort, and then performs the actual field request. It cannot also specify a fixed effort or budget.

Decoding and diagnostics

Generate accepts mode (argmax or sample), temperature, seed and numeric_max_digits (default 32). Positive temperature alone enables sampling; explicit argmax stays greedy. Level distributions use level names. Failed generation retains reported usage. The Dice cookbook recipe includes sampling, numeric limits and runtime-specific prompt diagnostics.

Option ordering

Keep the full candidate set visible to the model. Unordered choices and ordered score scales require different treatment: the positions of calm, annoyed, furious define the score; routing keys have no ordinal meaning.

Evaluate policies

Policy Choice work for K candidates Aggregation
none (default) Single pass Ordinary candidate scoring
cyclic K caller-order rotations Aligned raw logits averaged before calibration
balanced K layouts for even K; 2K for odd K Canonical Williams layouts; calibrate each layout, then average key-aligned probabilities

Correction applies only to choice. Mixed requests keep score and noul in an ordinary batch. The corrected core supports up to 32 choice candidates, but a selected runtime can impose a smaller limit. Browser finite scoring supports up to 24. Four choices cost four layouts; three cost six in balanced mode. The result is not recalibrated after averaging.

Generated enums

generate uses per-field permutations instead of the engine policy. auto builds canonical balanced layouts; positive integer budgets sample reproducibly using seed and include the original listing; all scores every permutation, capped at 720. Integer budgets are not generally invariant to caller reorderings. Numeric enums remain unordered; use evaluate with score for ordinal scales.

Validation and cost

Corrections reduce position sensitivity; they do not establish correct reasoning or calibrated confidence. Fit calibration against the selected policy and measure total latency. In the recorded Windows x64 Qwen3 0.6B Q4_K_M CPU probe, 18/18 routing decisions passed across three cases, three orders and two policies. Balanced distributions had zero keyed drift in that sample; single-pass drift reached 13.7 percentage points. This small sample is not a general accuracy or navigation guarantee.

Validation report and reproduction. Corrected responses expose _turbojev.order_robustness and order_evaluations. In default mode the latter is legacy zero, not an inference-call counter. Score training data preserves the scale and varies output codes; regenerate older materialized score data before further training.

Design a decision the model can answer

TurboJev executes the requested decision contract. Task accuracy depends on the checkpoint, instructions and evidence. A small model can route a clear message yet fail navigation or coordinate arithmetic.

Build the request

  1. State the facts needed for the decision; remove redundant prose.
  2. Ask one precise question with meaningful candidate keys and distinct descriptions.
  3. Keep every candidate visible; use an ordered score only when its sequence defines a real scale.
  4. Handle required safety and legality rules in the application, and disclose that policy.

Perception and policy

A game can expose raw coordinates or derive sensor facts such as nearby obstacles. Disclose derived observations as perception assistance. If a demo claims model-controlled movement, apply the returned direction unchanged and record collisions as failures. A host-computed path or a substituted move must not be counted as an AI decision.

Measure quality and speed together

Test known answers, failure cases and different candidate orders with the exact model, quantization, device and runtime you will ship. Separate download, load, preprocessing and decision time. Compare none with balanced only when the added evaluations help your task. Thinking generates tokens and adds latency; it is not automatically more accurate.

Use evals/run.py for recorded numeric and JevBench evaluations, and scripts/validate-real-option-order.mjs for the real option-order probe. Record request, output, model provenance, errors and latency; never reuse another engine's published scores as TurboJev evidence.
