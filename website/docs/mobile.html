Android + Swift

Both mobile bindings call the C ABI on a dedicated affinity thread.

sources ↗
Kotlin 
val jev = TurboJev.load(
    JSONObject("{\"model\":\"app/model.gguf\"}")
).join()
val request = """{"state":{"message":"My package arrived broken"},"questions":{"department":{"type":"choice","instructions":"Which department?","criteria":{"billing":"Payments","shipping":"Delivery"}}}}"""
val result = jev.evaluate(JSONObject(request)).join()
jev.close()
Swift 
let jev = try TurboJevEngine(

    optionsJSON: #"{"model":"model.gguf"}"#

)

let json = try jev.evaluate(#"{"state":{"message":"My package arrived broken"},"questions":{"department":{"type":"choice","instructions":"Which department?","criteria":{"billing":"Payments","shipping":"Delivery"}}}}"#)

try jev.close()

Generate typed fields

Use the same scalar request JSON as the other bindings. Native libraries must be built and packaged for the target platform; Android and Swift are source integrations, not claims of published mobile binaries.

Kotlin 
val fields = JSONObject("""{"context":"Invoice total: 324.50 GBP.","questions":{"total":{"type":"number","instructions":"What is the total in GBP?"}},"thinking":false}""")

val response = jev.generate(fields).join()
Swift 
let response = try jev.generate(#"{"context":"Invoice total: 324.50 GBP.","questions":{"total":{"type":"number","instructions":"What is the total in GBP?"}},"thinking":false}"#)

These calls belong before the engine close shown above. Native load options, field dependencies, conditions and budgets use the same JSON contract.
